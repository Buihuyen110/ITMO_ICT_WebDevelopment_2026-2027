    Отчёт лабораторной работы №2

    Цель работы

    Oвладеть практическими навыками и умениями реализации web-сервисов средствами Django.

    Программное обеспечение: Python 3.6+, Django 3, PostgreSQL.

    1. Вариант задания

    Вариант 4 — «Список туров туристической фирмы».

    Основной объект приложения - туристический тур, для которого хранятся название, страна назначения, туристическая компания, описание, даты начала и окончания поездки, стоимость и информация о доступных местах.

    Приложение должно предоставлять следующие возможности: - просмотр списка доступных туров и подробной информации о каждом туре

    • регистрацию и авторизацию пользователей

    • поиск и фильтрацию туров

    • оформление бронирований с учётом количества доступных мест

    • просмотр, редактирование и отмену собственных бронирований

    • публикацию отзывов с текстом и оценкой от 1 до 10

    • подтверждение бронирований администратором

    • просмотр статистики количества бронирований и выручки в разрезе стран

    Пользовательские функции и административные операции должны быть разграничены. Пользователь управляет собственными бронированиями и отзывами, а сотрудник с соответствующими правами может просматривать статистику и выполнять административные действия.

    3. Модель данных

    Для хранения данных приложения используется PostgreSQL. Подключение к базе данных настроено в settings.py Django. Модели описаны в tours/models.py, а взаимодействие с базой данных осуществляется с помощью ORM Django.

    Основные модели:

    Модель Назначение
    Country Страны назначения
    TourCompany Туристические компании
    Tour Информация о турах, стоимость и доступные места
    Booking Бронирования пользователей и их статусы
    Review Отзывы и оценки туров
    TourImage Дополнительные изображения туров

    Связи между моделями реализованы с помощью внешних ключей. Каждый тур связан со страной и туристической компанией. Бронирование связывает пользователя с выбранным туром, а отзыв содержит информацию об авторе, туре, тексте и оценке от 1 до 10.

    Для бронирований предусмотрены статусы pending, confirmed и cancelled, соответствующие ожиданию подтверждения, подтверждению и отмене.

    4. Реализация основных функций

    4.1. Каталог туров

    На главной странице отображается список активных туров. Пользователь может искать туры по названию, фильтровать их по стране и сортировать по стоимости или дате начала. Для удобства навигации реализована пагинация.

    "country", "company"
)

search_query = request.GET.get("q", "").strip()
if search_query:
    tours = tours.filter(title__icontains=search_query)

selected_country = request.GET.get("country", "")
if selected_country.isdigit():
    tours = tours.filter(country_id=int(selected_country))

selected_sort = request.GET.get("sort", "date")
if selected_sort == "price_asc":
    tours = tours.order_by("price", "start_date")
elif selected_sort == "price_desc":

paginator = Paginator(tours, 6)
page_obj = paginator.get_page(request.GET.get("page"))

    4.2. Регистрация и авторизация

    Регистрация реализована с помощью RegistrationForm, основанной на UserCreationForm. После успешной регистрации пользователь автоматически входит в систему. Для авторизации используется стандартное представление Django LoginView.

    Форма регистрации

    class RegistrationForm(UserCreationForm):
    email = forms.EmailField(required=True)

    class Meta:
        model = User
        fields = ('username', 'email', 'password1', 'password2')

    Обработка регистрации

    def register(request):
    if request.method == "POST":
        form = RegistrationForm(request.POST)
        if form.is_valid():
            user = form.save()
            login(request, user)
            return redirect("home")
    else:
        form = RegistrationForm()

    return render(
        request,
        "tours/register.html",
        {"form": form},
    )

    4.3. Подробная информация о туре

    Для каждого активного тура предусмотрена отдельная страница. На ней отображаются название, описание, страна назначения, туристическая компания, даты поездки, стоимость и количество свободных мест. Если изображения добавлены к туру, они отображаются в галерее.

    На этой же странице пользователь может перейти к бронированию и ознакомиться с отзывами. Для просмотра тура используется представление tour_detail, которое получает данные тура и связанные с ним отзывы из базы данных.

    
tour = get_object_or_404(

reviews = (
    Review.objects

    Метод select_related() используется для загрузки связанных данных страны и туристической компании, а prefetch_related() — для получения изображений тура. Отзывы сортируются по дате публикации в обратном хронологическом порядке.

    4.4. Создание и управление бронированиями

    Бронирование доступно только авторизованным пользователям. В форме необходимо указать количество человек. При отправке заявки система проверяет корректность данных и наличие свободных мест.

    Для согласованного изменения количества свободных мест и создания бронирования используется транзакция базы данных. Блокировка записи тура позволяет избежать одновременного изменения доступного количества мест несколькими запросами.

    Форма бронирования

    class BookingForm(forms.ModelForm):
    class Meta:
        model = Booking
        fields = ("people_count",)
        labels = {
            "people_count": "Количество человек",
        }
        widgets = {
            "people_count": forms.NumberInput(
                attrs={"min": 1, "value": 1},
            ),
        }

    Создание бронирования

    with transaction.atomic():
    tour = get_object_or_404(
        Tour.objects.select_for_update(),
        pk=pk,
        is_active=True,
    )

    if people_count > tour.available_places:
        form.add_error(
            "people_count",
            "Недостаточно свободных мест.",
        )
    else:
        tour.available_places -= people_count
        tour.save(update_fields=["available_places"])

        booking = form.save(commit=False)
        booking.user = request.user
        booking.tour = tour
        booking.status = Booking.Status.PENDING
        booking.save()

    После создания заявки пользователь перенаправляется в раздел личных бронирований. Новая заявка получает статус pending и ожидает подтверждения администратором.

    4.5. Личные бронирования

    В разделе «Мои бронирования» пользователь видит список собственных заявок, включая информацию о туре, стране, количестве человек, дате создания и текущем статусе. Для заявок, ожидающих подтверждения, доступны редактирование количества человек и отмена.

    Получение бронирований текущего пользователя

    Получение бронирований текущего пользователя (views.py)

@login_required
def my_bookings(request):
    bookings = (
        Booking.objects
        .filter(user=request.user)
        .select_related("tour", "tour__country")
    )

    return render(
        request,
        "tours/my_bookings.html",
        {"bookings": bookings},
    )

    Декоратор login_required ограничивает доступ к разделу авторизованными пользователями. Фильтрация по request.user гарантирует, что в списке отображаются только бронирования текущего пользователя.

    Редактирование и отмена разрешены только для заявок со статусом pending. При отмене заявки количество свободных мест восстанавливается.

    4.6. Отзывы

    Авторизованные пользователи могут публиковать отзывы на странице тура. Форма содержит текст отзыва и оценку от 1 до 10. Имя автора, дата публикации и связь с выбранным туром сохраняются автоматически на сервере.

    Форма отзыва

    class ReviewForm(forms.ModelForm):

        }

if Review.objects.filter(

    4.7. Панель администратора

    Для управления данными используется Django Admin. Администратор может управлять турами, странами и туристическими компаниями, а также подтверждать ожидающие бронирования.

    Административное подтверждение бронирований

    @admin.action(
    description="Подтвердить выбранные бронирования"
)
def confirm_bookings(modeladmin, request, queryset):
    updated = queryset.filter(
        status=Booking.Status.PENDING
    ).update(
        status=Booking.Status.CONFIRMED
    )

    modeladmin.message_user(
        request,
        f"Подтверждено бронирований: {updated}",
        level=messages.SUCCESS,
    )

    Действие изменяет статус только у выбранных заявок, находящихся в состоянии pending. После выполнения администратор получает сообщение о количестве подтверждённых бронирований.

    4.8. Статистика бронирований по странам

    Для пользователей с правами персонала предусмотрена отдельная страница статистики. Данные группируются по стране назначения. Для каждой страны отображаются общее количество непринятых к отмене заявок, количество подтверждённых бронирований и выручка по подтверждённым заявкам.

    Расчёт статистических показателей

    @staff_member_required
def country_statistics(request):
    countries = Country.objects.all().order_by("name")

    statistics = Booking.objects.values(
        "tour__country_id"
    ).annotate(
        total_bookings=Count(
            "id",
            filter=~Q(status=Booking.Status.CANCELLED),
        ),
        confirmed_bookings=Count(
            "id",
            filter=Q(status=Booking.Status.CONFIRMED),
        ),
        revenue=Sum(
            F("people_count") * F("tour__price"),
            filter=Q(status=Booking.Status.CONFIRMED),
        ),
    )

    Общее количество бронирований не включает отменённые заявки. Выручка рассчитывается только по подтверждённым бронированиям как произведение количества человек на стоимость тура.

    Доступ к странице ограничен декоратором @staff_member_required. Результаты расчётов передаются в шаблон country_statistics.html, где отображаются в табличном виде.

    4.9. Разграничение доступа

    В приложении предусмотрены разные уровни доступа: - неавторизованные посетители могут просматривать каталог и страницы туров, а также регистрироваться и входить в систему; - авторизованные пользователи могут создавать бронирования, просматривать собственные заявки и публиковать отзывы; - пользователи с правами персонала дополнительно получают доступ к статистике и административной панели.

    Проверка доступа реализована средствами Django: используются декораторы login_required и staff_member_required, а также проверка принадлежности бронирования текущему пользователю.

    5. Автоматизированное тестирование

    Для проверки корректности работы веб-приложения были разработаны автоматизированные тесты с использованием Django TestCase.

    Тесты охватывают основные функции приложения: - отображение списка активных туров; - скрытие неактивных туров; - регистрацию нового пользователя; - ограничение доступа неавторизованных пользователей к своим бронированиям; - создание бронирования и уменьшение количества доступных мест; - проверку доступности мест при бронировании; - отмену бронирования со статусом pending и восстановление доступных мест; - добавление отзыва к туру; - проверку доступа к статистике по странам для сотрудников; - ограничение доступа обычных пользователей к статистике.

    Для запуска тестов использовалась команда:

    python manage.py test tours

    По результатам выполнения все автоматизированные тесты завершились успешно.

По результатам тестирования основные функции приложения работают корректно.

    7. Запуск проекта

    Для запуска веб-приложения необходимо выполнить следующие действия.

    Перейти в корневую директорию проекта и создать виртуальное окружение Python:

    python -m venv venv

    Активировать виртуальное окружение.

    Для Windows:

    venv\Scripts\activate

    Установить необходимые зависимости:

    pip install -r requirements.txt

    Установить и запустить PostgreSQL, создать базу данных tourism_db и настроить параметры подключения в файле конфигурации проекта.

    Выполнить миграции Django для создания необходимых таблиц базы данных:

    python manage.py migrate

    При необходимости создать учётную запись администратора:

    python manage.py createsuperuser

    Запустить локальный сервер разработки:

    python manage.py runserver

    После запуска приложение доступно по адресу: http://127.0.0.1:8000/

    Панель администратора Django доступна по адресу: http://127.0.0.1:8000/admin/

    Для завершения работы сервера необходимо нажать Ctrl + C в терминале.
